# Trace — 就活のための自己分析日記

> 生成AIを用いた独自サービスの実装（最終課題）。
> 開発は **Coding Agent（Claude Code）を使ったバイブコーディング／ループ開発**で行い、
> この README がサービス内容・生成AIの活用・開発手法・実装の説明を兼ねる提出ドキュメントです。

**Trace は、日記を「書くこと」自体が目的ではなく、就職活動の自己分析の材料を貯めるための日記アプリ**です。
毎日の感情・行動・目標の傾向を時間をかけて可視化し、貯まったデータを就活の成果物（強み・STARエピソード）へ変換します。

Next.js（App Router）+ TypeScript + Tailwind の PWA。データは**すべてブラウザ内（IndexedDB）にローカル保存**で、サーバーには貯めません。

---

## 1. サービス概要

### 解決する課題
大学生が抱える3つの課題を1つのループでつなぎます。

1. **計画が立てられない** … 「今日やること」を話し言葉で入れると AI が1日のタイムブロックの下書きを提案。
2. **計画が続かない** … 書く・集中する・目標を進めるすべてが XP になり、木が育つ**報酬ループ**で継続を後押し。
3. **自己分析の素材がない** … 日々の日記を AI が感情スコア＋活動タグに変換し、就活時に**強み仮説・STARエピソード**として引き出せる。

### 独自性（差別化）
カレンダー／ToDo／AIスケジューラ／感情日記はいずれも既存にありますが、**「予定（行動）」と「感情」を同一の AI で扱い、就活の自己分析まで接続する**サービスは空白領域でした。Trace はこの一本の流れ（書く → AIが読み取る → 傾向が見える → 就活の成果物になる）を中心に据えています。

## 2. 生成AIの活用（このアプリのコア）

生成AI（Google **Gemini**）を、アプリの中核機能として5つの用途で使っています。

| 用途 | 内容 | 実装 |
|---|---|---|
| 感情分析 | 日記本文から感情スコア・感情ラベル・キーワードを抽出 | `/api/analyze` |
| 活動分類 | 本文の主タスクをカテゴリに分類（修正はプロンプトに反映） | `/api/classify` |
| 1日の組み立て | やること＋起床/就寝から時間割の**下書き**を生成 | `/api/plan` |
| 時間割の構造化 | 「月3限に統計学…」等の自然言語を曜日・時刻・科目に構造化 | `/api/timetable` |
| 就活の成果物 | 蓄積した日記から**強み仮説**と**STARエピソード**を生成 | `/api/strengths` `/api/star` |

**貫いている2つの原則:**

1. **AI は提案（下書き）まで。決定権は人間。** 生成物はすべて編集・削除・追加でき、根拠まで辿れます。「AI が勝手に決める」構造にはしていません。
2. **捏造させない。** 就活の強み／STAR は、根拠にできるのが**実際に存在する日記の日付だけ**。サーバー側で入力に無い日付を除外するので、AI が事実を盛れません。

> モデルはコードに固定せず `.env` の指定のみを使う設計（現在 `gemma-4-31b-it`）。API キーはサーバー側でのみ読み、ブラウザから直接 Gemini を叩きません。

## 3. 開発手法（Coding Agent／バイブコーディング／ループ開発）

本課題の要件どおり、**Coding Agent（Claude Code）との対話でコードを書き進めるバイブコーディング**、および**小さく作って実際に触り、気づきを即反映するループ開発**で構築しました。

- **バイブコーディング**: 仕様を会話で詰め、AI にコードを生成させ、都度 `npm run typecheck` / `npm run build` で検証しながら前進。
- **ループ開発（実際に使って直した例）**:
  - 気分は手動選択をやめ、**AI が本文から自動判定**する読み取り専用に変更。
  - ホーム／目標から「今日の一手」を撤去し、目標の最小段を**週次**までに簡素化。
  - 予定生成で **AI の語彙が崩れる**（壊れた記号混入）事象に、タイトルの検証ガードを追加。
  - 空DBだと価値が伝わらない問題に、**デモデータ＋3画面オンボーディング**を追加（分析は本物の Gemini を 30 req/分で実行）。
  - 公開時のアクセス制御として**パスワードログイン**（`/login`）を追加。
- **検証方針**: テスト専用ランナーは持たず、`npm run typecheck` + `npm run build`、および IndexedDB を触る箇所は `fake-indexeddb` の使い捨てスクリプトで確認。

## 4. 主な機能

下部タブは **今日 / 組立 / 目標 / 記録** の4つ。**集中**・**就活の自己分析**・**設定**はヘッダーメニューから開きます。

| 画面 | 内容 |
|---|---|
| **今日**（ホーム） | 報酬ハブ＝挨拶・連続記録の炎バッジ・**育つ木**・レベル/XPバー・**いま／次カード**。その下が日記入力（3秒デバウンスで自動保存）。気分は AI が本文から自動判定して表示 |
| **組立** | 「やること」と毎日の「習慣」を登録し（やることは任意で時刻を固定可）、起床/就寝と合わせて AI が1日の**下書き**を提案。授業などの**時間割は自然言語で登録**でき（末日を過ぎると一覧・生成から自動で消える）、生成時はそれを固定として**空き時間だけ**を埋める。**24時間ダイヤル**＋種別内訳・達成率。各ブロックは完了・編集・削除・手動追加が自由で、自然言語で再調整も可。カレンダーで先の日も計画可能 |
| **目標** | 大目標 → 「3ヶ月後どうなっていたい？」「今週やることは？」に**人間が**答えて具体化。最小の段は週次で、チェックすると上位の進捗が自動更新（AI 分解は不採用） |
| **記録／分析** | **記録**＝年間ヒートマップ・連続記録・週次ふりかえり。**分析**＝週/月/年で感情スコア・記入率・ラベル構成比・キーワード・活動カテゴリ・集中時間・傾向インサイト |
| **就活の自己分析** | 「あなたの傾向」（非AI集計）＋ AI の**強み仮説**／**STARエピソード**。根拠は各日の日記にリンク（捏造防止つき） |
| **集中** | カテゴリ＋時間のポモドーロ的タイマー。実行中セッションは開始時刻を保存し、リロードをまたいでも復元。完了で XP を獲得 |

## 5. 技術構成

**Next.js 15（App Router）/ TypeScript / Tailwind 3 / React 19 / Recharts / Dexie（IndexedDB）/ Gemini API**

3層のシンプルな構成です。

```
ブラウザ(PWA)  ──  Next.js API ルート（薄いプロキシ）  ──  Gemini API
  IndexedDB          APIキー秘匿・入出力の検証のみ            生成・分析
（全データhere）        ステートレス
```

- **データは端末内 IndexedDB のみ**。認証・外部 DB（Supabase 等）は使いません → サーバー運用コストとプライバシーリスクを同時に抑制。
- API ルートは**キー秘匿と出力の検証**だけを担当（例: 予定は壊れたブロックを捨てる、就活は入力に無い日付を除外）。
- **本文と分析結果は別テーブル**（`entries` / `analyses`）で保存し、分析に `model`/`promptVersion` を記録 → 後から新しいモデルで再解析できる。
- **分析の失敗は保存を妨げない**（失敗は `analysisJobs` に積み、起動時・オンライン復帰時に再試行）。

### 主なディレクトリ
```
src/app/            画面（today/plan/goals/record/insights/focus/jobhunt/settings/login）
src/app/api/        サーバー処理（analyze/classify/plan/timetable/strengths/star/login）
src/components/     UI コンポーネント
src/lib/            db(Dexie)・stats・growth・plan・focus・goals・gemini など中核ロジック
src/middleware.ts   パスワードログイン（本番で SITE_PASSWORD 設定時のみ有効）
```

## 6. セットアップ / 起動

```bash
npm install
npm run dev          # http://localhost:3000
```

初回はオンボーディング（3画面）が出ます。**「デモデータを入れて試す」**を選ぶと約50日ぶんのサンプルが入り、空の画面を見ずに中身を体験できます（設定からいつでも消去可）。

### AI 機能を使う場合
`.env.example` を `.env` にコピーし、キーを記入してください。

```
GEMINI_API_KEY=（https://aistudio.google.com/apikey で取得）
GEMINI_MODEL=gemma-4-31b-it
SITE_PASSWORD=          # 任意。設定すると本番で /login のパスワードが必要になる
```

**キーが無くても、日記の入力・保存・ヒートマップ・目標・集中・エクスポートは動きます**（AI 分析だけがスキップされ、キューに積まれて後で再試行）。

### コマンド
| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバー |
| `npm run build` | 本番ビルド |
| `npm run start` | ビルド済みアプリの起動 |
| `npm run typecheck` | 型チェック（`tsc --noEmit`） |

## 7. データとプライバシー

- 日記はブラウザの **IndexedDB**（DB名 `trace`）にのみ保存され、**端末・ブラウザをまたいで共有されません**（デプロイしても閲覧者それぞれのブラウザに別々に貯まる）。移行は JSON のエクスポート／インポートで。
- ブラウザのサイトデータを消すと日記も消えるため、設定タブから Markdown / JSON でエクスポートできます。
- 外部に出るのは**分析時の日記本文のみ**（サーバー経由で Gemini へ）。API キーはサーバーでのみ扱います。
